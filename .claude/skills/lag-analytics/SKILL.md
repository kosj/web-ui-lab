# 렉 분석 스킬

참조 구현은 `boards/lag-board/src/analytics/`와 `src/data/`에 있다. 임계값 근거는 `knowledge/lag-thresholds.md`, 통계 메모는 `knowledge/references.md` §3에 있다.

## 1. 체감 지연(EL) — 모든 신호를 ms 하나로

```
EL = 네트워크 + 서버 + 클라
네트워크 = RTT p95 + 1.5×지터 + 50ms×손실률(%)
서버     = ½×틱 p99 + 1.5×max(0, 틱 p99 − 틱예산 50ms)
클라     = ½×프레임 p95 + 1.5×max(0, 프레임 p95 − 50ms)
```

- 가법이라 원인별 누적 분해가 가능하고, 단위가 ms라 연구 임계값을 그대로 적용할 수 있다.
- 지터·손실 가중치는 MMORPG 이탈 민감도(지연 1 : 지터 2 : 손실 3~4, Chen et al. 2006)에서 왔다. 손실 1% → 50ms는 TCP 재전송(RTO) 전가를 근사한 값이다.
- 장르가 다르면(논타겟 액션, FPS) 계수와 틱 예산을 다시 정한다.

## 2. 등급 임계값 (MMORPG, RTT 환산)

| 쾌적 | 양호 | 주의 | 경고 | 심각 |
|---|---|---|---|---|
| <100 | 100–150 | 150–250 | 250–500 | ≥500 |

- 근거: 인지 하한 ~100ms(Raaen), 150ms 유저 평균 4시간·250ms 유저 평균 1시간 플레이(Chen), 3인칭 RPG 허용 상한 ~500ms(Claypool).
- "렉 체감 유저" = EL ≥ 150ms 서버의 동접 합.
- 실서비스에서는 자사 데이터로 재보정한다(지연 구간별 세션 길이 생존 분석).

## 3. 집계

- 권역·전역 값은 **동접 가중 분위수**(`weightedQuantile`)로 구하고, 서버별 p95를 평균내지 않는다. 원시 히스토그램이 있으면 병합해서 다시 계산하는 게 가장 좋다.
- 원인 분해만 가중 평균(가법)을 쓰고, 라벨에 "평균"이라고 명시한다.

## 4. 이상 탐지 파이프라인 (`attribution.ts`, `incidents.ts`)

1. **기준선**: 전일 동시간대 ±45분 **중앙값과 MAD**를 5분마다 갱신한다. 12h 롤링 창은 일주기 피크를 오탐하므로 쓰지 않는다. 데이터가 4주 이상 쌓이면 같은 요일·시각 4주 중앙값으로 확장한다.
2. **z**: EWMA(α=0.35)로 평활한 값에 강건 z = (x − med) / max(1.4826·MAD, floor)를 계산한다. floor는 성분별로 net 3ms, srv/cli 1.5ms, steal 0.4%, io 0.5%다.
3. **초과분**: max(0, x − med) × 게이트. 게이트는 z가 2.5→4.5 구간에서 0→1로 오른다.
4. **인프라 이관**: 호스트 z(steal, I/O)가 2.5→5.5 구간에서 오른 비율만큼 서버 초과분을 인프라로 넘긴다.
5. **토폴로지 규칙**: 같은 랙 2대 이상이 동시에 서버측 초과 ≥ 20ms면 인프라로 재분류한다.
6. **장애 묶기**: 원인별 범위 키로 묶는다(인프라=랙, 네트워크=권역, 서버=단일 서버, 클라=전역). 클라는 전체 서버의 20% 이상일 때만 장애로 본다. 공백 5분 이하는 이어 붙이고, **활성 분이 5분 이상**인 것만 남긴다.
7. **시작·감지**: 구성 서버 평균 z에 CUSUM(k=0.5, h=5)을 돌린다. **이후 10분 평균 z > 2가 유지된 첫 경보**를 감지 시각으로 잡고, 그 경보 직전 S=0 지점을 시작 시각으로 잡는다.
8. **신뢰도**: ½ × 원인 점유율 + ½ × 패턴 일치도. 근거는 범위·신호·배제 3종으로 문장화한다. 배제 근거(예: "RTT 정상")가 판정의 설득력을 만든다.

## 5. 원인별 서명 (판별 표)

| 원인 | 신호 | 범위 | 배제 |
|---|---|---|---|
| 인프라 | CPU steal·I/O 대기↑, 틱↑ | 같은 DC 랙 여러 대 | 같은 권역 다른 랙 정상, RTT 정상 |
| 네트워크 | RTT p95·지터·손실↑ | 권역 전체(랙 무관) | 서버 틱 정상 |
| 서버 | 틱 p99↑(예산 초과) | 서버 1대 | 같은 권역 다른 서버 정상, 호스트 정상 |
| 클라 | 프레임 p95↑, 신버전에서만 | 전 권역 동시 | RTT·틱 정상, 패치 시각과 상관 |

## 6. 가상 데이터와 회귀 테스트

- 생성기(`data/generate.ts`)는 시드를 고정한다(mulberry32). 동접 일주기(05:30 최저, 21:30 최고), 부하 비례 지표, 0.2% 단발 버스트를 넣는다.
- **기간**: 49h(워밍업 25h + 표시 24h).
- **시나리오**(`data/config.ts` `SCENARIOS`)는 정답 원인·범위·시작·종료를 담는다. 분류기는 시나리오를 보지 않는다.
- 시나리오 강도는 램프업(분)으로 조절한다. 데모 데이터에는 대비가 있어야 한다. 렉 체감 유저가 전체의 100%가 되면 실패다.
- **테스트**(`src/analytics/__tests__/scenario.test.ts`) 기준:
  - 시나리오당 장애 정확히 1건
  - 원인·범위 일치
  - 시작 오차 ±10분
  - 진행 여부 일치
  - 신뢰도 > 0.7
  - 조용한 시간대 오탐 없음
- 판별 로직이나 파라미터를 바꾸면 `npm test`가 통과해야 한다. 오탐을 줄이려 테스트를 완화할 때는 learnings에 이유를 적는다.

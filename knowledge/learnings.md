## #1 렉 보드 v0.1 (2026-11-14)

### 결정과 이유

| 주제 | 결정 | 이유 |
|---|---|---|
| 정보 구조 | 요약 배너 → KPI → 권역×시간 히트맵 + 장애 판정 → 원인 분해 → 서버 그리드(권역→랙) → 서버 상세 → 방법 노트 | "어디서·언제부터·왜"를 위에서부터 답하고, 아래로 갈수록 근거가 구체화되는 깔때기 |
| 단일 지표 | 모든 렉 신호를 ms 하나(체감 지연 EL)로 환산 | 연구 임계값(100/150/250/500ms)을 그대로 쓰고, 성분이 가법이라 원인별 누적 영역으로 분해 가능 |
| 집계 | 권역·전역은 **동접 가중 p95**, 원인 분해만 가중 평균 | 꼬리 지연은 평균이 가린다. 분해는 가법성이 필요해서 평균을 쓰되 라벨로 명시 |
| 기준선 | **전일 동시간대 ±45분 중앙값** | 12h 롤링 중앙값은 저녁 피크를 이상으로 오탐(EU·NA 1시간짜리 가짜 장애 2건) → 계절성 기준선으로 해결 |
| 노이즈 | EWMA(α=0.35) 평활 z + 활성 5분 이상만 장애 | 단발 패킷 버스트로 생긴 6분짜리 가짜 장애 제거. "구간 길이"가 아니라 "활성 분 수"로 세야 한다 |
| 원인 판정 | 신호(z) + 토폴로지(같은 랙 2대↑ → 인프라) 2단계 | 지표만으로는 "서버 틱 증가"가 서버 탓인지 호스트 탓인지 모른다. 확산 범위가 결정적 단서 |
| 시작 시각 | CUSUM(k=0.5,h=5), **이후 10분 평균 z>2가 유지된 첫 경보** 채택 | 첫 경보를 무조건 쓰면 일시 경보 뒤의 리셋 때문에 시작이 24분 늦게 잡혔다 |
| 원인 색 | blue·aqua·violet·magenta (dataviz 기준 팔레트 슬롯 1·3·7·5) | 상태색(노랑·주황·빨강)과 겹치지 않게. 인접쌍 CVD ΔE 16+(다크) 검증. 리서치 노트의 Okabe-Ito 안은 인프라·네트워크 상호 대비 2.25:1이라 채택 안 함 |
| 상태 표현 | 색 + 아이콘 모양 + 한글 라벨, 필 안 글자는 노랑·주황엔 짙은 글자 | 색만으로 전달 금지. 주황(#ec835a) 위 흰 글자는 2.6:1이라 짙은 글자로 바꿈 |
| 크롬 | UI 컨트롤·선택·포커스는 무채색 | 색(hue)은 데이터·상태 전용. 선택 링은 잉크색 |
| 테마 | 다크 우선, 라이트 동등 지원. 호스트가 data-theme을 주면 따름 | 관제실 기본 + 사무실 공유 |
| 시간축 | 카테고리 축 + 직접 만든 KST 라벨, **구간 끝 시각**으로 라벨 | ECharts time 축은 브라우저 시간대를 따름. 시작 시각 라벨은 21:01처럼 정각이 어긋남 |
| 표 대안 | 히트맵·원인 분해에 "표로 보기" 토글 | 툴팁만으로 값을 읽게 하지 않는다 |
| 피드 상태 | 상단에 "수집 정상 · 36/36 서버" | 측정이 멈췄는데 정상으로 보이는 사고 방지 (Riot MSI 2022 사례) |

### 시각 QA에서 잡은 버그

- 렉 체감 유저 100% → 시나리오 강도 과다. 데모 데이터도 "대비"가 있어야 판단이 보인다(47%로 조정).
- 장애 레인 라벨 겹침 → 레인 높이 13→17px, `interval: 0`.
- 서버 그리드 6권역이 5+1로 줄바꿈 → 6열/3열/2열/1열 브레이크포인트로 고정 (혼자 남는 행 금지).
- 축 최대값 136.54 같은 소수 → `niceCeil`(1·2·2.5·5×10ⁿ).
- 임계선 라벨이 오른쪽 끝 데이터와 겹침 → `insideStartTop`(왼쪽)으로. 최신 데이터는 오른쪽에 몰린다.
- 모바일 히트맵 라벨 뭉개짐 → `hideOverlap: true` + 24h는 2시간 간격.
- 좁은 타일에서 "경고"가 "경/고"로 줄바꿈 → `white-space: nowrap` + foot `flex-wrap`.
- SVG 스파크라인을 `preserveAspectRatio=none`으로 늘리면 끝점 원이 타원이 됨 → 끝점은 HTML로 겹쳐 그림.

### 백로그 (리서치에 있으나 v0.1에 미반영)

## #2 렉 보드 v0.2 — 지연 분포 히트맵 + 통신사 드릴다운 (2026-11-14)

### 결정과 이유

| 주제 | 결정 | 이유 |
|---|---|---|
| 데이터 구조 | **권역 × 통신사 경로**를 1차 데이터로, 서버 RTT는 그 서버 유저의 통신사 혼합으로 합성 | 드릴다운 수치와 서버 지표가 서로 맞물려야 신뢰가 생긴다. 실제 네트워크도 경로(통신사→DC)가 서버보다 상위 단위 |
| 분포 모델 | 통신사별 RTT를 (p50, p95)로 맞춘 **로그정규**, 유저 EL = RTT + 고정 성분(지터·손실·서버·버전별 클라) | p50/p95 두 값만으로 분포 복원 가능, CDF가 해석적이라 표본 추출 없이 매끈하고 재현 가능 |
| 혼합 분위수 | 로그 공간 이분 탐색(12~16회) | 혼합 분포는 닫힌 해가 없다. 서버 단위로 돌리면 2배 느려져 권역 단위로 1회 계산 |
| 분포 축 | 로그 눈금, 구간 경계에 등급 임계값(100·150·250·500) 포함 | 지연은 오른쪽 꼬리가 길다. 경계와 임계값이 맞아야 "150ms 이상 비율"이 정확 |
| 분포 색 | **밀도 = 비율 ÷ 로그 폭**, 감마 0.45 + 하한 0.1, 무채 슬레이트 단일 램프 | 비율로 칠하면 좁은 구간이 흐려 보인다. 원인·상태 hue와 겹치지 않게 무채 |
| 겹친 선 | p50·p95 선 아래 **표면색 테(halo)** | 진한 칸 위에서도 선이 보이게. dataviz의 surface ring 원칙 |
| 두 갈래 안내 | 봉우리 2개(각 8%↑) + 골짜기 < 작은 봉우리 60% + **느린 쪽 ≥150ms** | 전체 범위는 권역마다 기본 지연이 달라 원래 여러 갈래 → 렉 구간 조건 없이는 상시 오탐 |
| 통신사 상태색 | 칸·행은 **경로 이상(z≥3, +15ms↑)**일 때만 칠함 | 클라 장애로 오른 체감 지연 때문에 모든 통신사가 "주의"로 칠해지는 오해를 막음 |
| 여러 통신사 선 | 강조 1개(선택 또는 변화 최대) + 나머지 회색, 끝 라벨 | 범주색 5개를 새로 쓰면 원인 4색과 충돌. dataviz "emphasis" 형식 |
| 판정 범위 | 네트워크 장애의 **통신사별 초과 지연 기여**(유저 비중 × 전일 대비 증가) 1위가 70%↑면 범위를 통신사로 좁힘 | "권역 전체" vs "특정 통신사 경로"는 대응 주체가 다르다(DC 네트워크팀 vs 통신사 연락) |
| 연동 | 장애 카드 → 권역·통신사·시점 일괄 선택, 분포 카드에 필터 칩(해제 가능) | 판정 근거를 클릭 한 번으로 화면에서 확인 |

### 검증

- 시나리오 S5(LG U+ 국제망 우회) 추가: 판정 범위 `isp`, 기여 99%, 시작 오차 1분.
- S2(동남아 케이블): 여러 통신사(PLDT 36%·IndiHome 36%·True 16%)라 권역 범위 유지 — 테스트로 고정.
- 분포: 구간 비율 합 1, 사고 중 한국 150ms↑ 비율 ≈ LG U+ 유저 비중, LG U+만 거르면 80%↑, 두 갈래 감지기는 정상 시간·전체 지리 분포에서 침묵.

### 시각 QA에서 잡은 것

- 1280px에서 통신사 표(6열)가 2단 배치로 잘림 → 나란히 배치는 1480px 이상에서만.
- 밀도 램프가 너무 어두워 희박한 칸이 안 보임 → 감마·하한 조정.

## #3 렉 보드 v0.3 — 모션 그래픽 (2026-11-14)

조사·규칙 전문은 `knowledge/motion.md`.

### 결정과 이유

| 주제 | 결정 | 이유 |
|---|---|---|
| 모션의 역할 | 시간 흐름(재생)·상태 변화(롤링·링)·흐름(패킷)만 | 관제 화면에서 장식 모션은 주의를 빼앗는다. 모든 모션이 "무엇이 바뀌었는지"를 말해야 한다 |
| 핵심 모션 | **장애 재생** — 커서 자동 진행 + 미래 흐림 | 사후 분석에서 "언제 무엇이 먼저 나빠졌나"를 순서대로 다시 보는 것이 가장 가치 있다 |
| 커서 구현 | 차트 옵션에서 커서를 빼고 HTML 오버레이로 | 커서가 옵션 안에 있으면 매 틱마다 차트 6개를 통째로 다시 그려 재생이 끊긴다. 오버레이는 transform만 바뀐다 |
| 재생 갱신률 | rAF로 흐르되 React 갱신은 120ms마다, 커서 전환도 120ms 선형 | 보드 전체 재계산 비용 제한 + 틱 사이를 CSS 전환이 메워 연속 이동처럼 보인다 |
| 토큰 | Carbon 지속시간·이징 + 스프링을 CSS `linear()`로 | 검증된 수치 재사용. linear()로 JS 없이 스프링 근사 |
| 숫자 | 자릿수 롤링, 고스트 숫자로 기준선 유지, tabular-nums | 롤링 중 폭이 흔들리면 읽기 어렵다(정적 큰 숫자 비례폭 규칙의 예외) |
| 경보 | 등급 상승 시에만 링 2회 (`useEscalation`) | 악화만 알린다. 반복 깜빡임은 피로·WCAG 문제 |
| 차트 전환 | 원인 분해·서버 상세는 series id 고정 merge로 모핑, 히트맵은 정적 | Heer & Robertson: 같은 마크가 같은 데이터를 유지해야 추적 가능. 칸이 많은 히트맵은 모핑 이득 없음 |
| 패킷 레인 | 속도=RTT, 흩어짐=지터, 사라짐=손실(×5 명시) | 입자 모션이 장식이 되지 않게 세 지표를 인코딩. 정지 모드도 같은 인코딩 |
| 접근성 | 상단 토글 하나로 전체 정지, 기본은 OS 설정, 화면 밖·탭 숨김 시 rAF 정지 | WCAG 2.2.2 (자동 갱신에는 5초 예외 없음) |
| 의존성 | 모션 라이브러리 없이 CSS + rAF + View Transitions | 번들 증가 없이 충분. GSAP 무료화(2025)는 복잡한 타임라인이 필요할 때 후보 |

### 버그·교훈

- 파이썬 스크립트에서 `open(p,'w').write(open(p).read())`는 읽기 전에 파일을 비운다 → 파일이 0바이트가 됨. 쓰기는 항상 읽은 뒤 별도 문장으로.
- 새 장애 카드의 `is-fresh`를 "이번 렌더에서 처음 봄"으로 계산하면 다음 재생 틱에 클래스가 빠져 등장 애니메이션이 끊긴다 → 처음 본 시각을 기억해 1초간 유지. 화면에서 사라진 장애는 잊어서 되감기 후 다시 등장하게.
- 재생이 현재 시각에 도달하면 재생 모드를 자동 종료해 LIVE로 복귀. 과거에서 끝나는 장애 재생은 그 시점에 멈춘 채로 둔다.
- 통신사 표에 열이 늘어 1600px에서 잘림 → 나란히 배치 기준을 1800px로.

## #4 렉 보드 v0.4 — 채팅 렉 제보 × TCP 재전송 (2026-11-14)

방법·근거·회수 결과 전문은 `knowledge/user-signals.md`.

### 결정과 이유

| 주제 | 결정 | 이유 |
|---|---|---|
| 핵심 질문의 형태 | "급증이 함께 일어나나"로 보고 **사건 동시발생 분석 + 사건 정렬 평균** | 드문 급증의 결합에는 연속 상관(교차상관)이 검정력이 없었다 |
| 비교 단위 | 모든 신호를 전일 동시간대 대비 편차로 (제보는 Anscombe 잔차) | 원값은 저녁 피크 공통 추세로 허위 상관 |
| 재전송의 역할 | 상관의 한 축이자 **원인 판별 신호** (재전송 동반 = 손실형, 없음 = 그 외) | 커널이 ACK를 보내는 한 서버·클라 문제로는 재전송이 늘지 않는다 |
| 효과 크기 | 분절 포아송 회귀(재전송·프레임 통제), 준포아송 φ로 구간 보정, 전체 서버로만 적합 | 권역 단위는 공선성으로 효과가 뒤집힘 |
| 사각지대 | 제보 급증 + 직전 15분 지표 평소 + 장애 앞뒤 15분 제외 | 제보 꼬리(최대 12분)를 사각지대로 오탐하던 문제 해결 |
| 화면 | 신호 연쇄(세 칸 공유 축) · 결합 카드(ECA 수치 + 정규화 사건 정렬) · 장애 지도 · 용량–반응 · 채팅 표본 | 이중 축 없이 "같이 움직임 → 순서 → 크기 → 사례" 순서로 읽힘 |

### 버그·교훈

- 서버 단위 분당 제보율의 중앙값 기준선이 0 → 기대치 0 → 배수 0. 건수 데이터의 기준선은 **합의 비**로.
- 제보 확률을 서버 평균 EL로 만들면 일부 통신사만 겪는 장애(LG U+ 21%)가 희석됨 → 통신사 집단별 위험률을 비중으로 섞는다(유저 단위 모델).
- 포화 없이 지수 모델만 쓰면 분당 33%가 제보 → 포화 함수 pMax(1−e^(−h/pMax))로 현실화.
- 손실형 장애의 유형이 '지연'으로 나옴 → 손실·재전송은 '끊김·튕김', RTT·지터는 '지연'으로 가중 분리.
- 롤링 숫자 자릿수가 flex 항목으로 늘어나(부모 줄높이 1.5) 다음 숫자가 비침 → `.rn { line-height: 1.15 }`, `align-items: flex-start`.
- 무작위 흐름이 바뀌면서 "조용한 시간 단발 버스트 ≤3분" 테스트가 4로 실패 → 테스트 의도(지속 상승 금지)에 맞게 "연속 3분 이상 없음"으로 수정.

## #5 렉 보드 v0.5 — 스타일 프리셋 5종 (2026-11-14)

근거·구조 전문은 `knowledge/styles.md`, 비교 갤러리는 `docs/style-gallery/`.

### 결정과 이유

| 주제 | 결정 | 이유 |
|---|---|---|
| 시안 구성 | 그래파이트 · 콕핏 · 터미널 · 에디토리얼 · 글래스 | "고급감"과 "시인성"을 각각 다른 방식으로 얻는 대표 계열을 하나씩 |
| 구현 방식 | 색 토큰 + 구조 토큰(서체 역할·카드·라벨·숫자)을 `[data-style]`로 일괄 교체, 시그니처만 별도 CSS | 컴포넌트는 그대로 두고 표현만 바꿔야 같은 데이터로 공정하게 비교된다 |
| 단일 테마 스타일 | 선택자 특이도 (0,3,0) + 테마 토글 잠금 | 콕핏·터미널은 다크, 에디토리얼은 라이트일 때만 성립하는 표현 |
| 원인 색 | 콕핏·터미널은 기존 검증 팔레트 유지, 글래스·에디토리얼은 면별 재검증 | 스타일을 바꿔도 "인프라=파랑"이 유지되어야 운영자가 헷갈리지 않는다 |
| 비교 방법 | 보드 안 실시간 전환 + `#style-<id>` 링크 + 스크린샷 갤러리 | 같은 시각·같은 데이터로 나란히 보고 고르게 |
| 추천 | 운영 = 콕핏, 보고·공유 = 에디토리얼, 데스크 = 그래파이트 | 원거리 판독성 vs 고급감 vs 장시간 피로의 균형 |

### 버그·교훈

- 테마·스타일 속성을 부모 effect에서 바꾸면 자식(차트)의 토큰 읽기가 먼저 돌아 한 박자 늦은 색을 읽는다 → 렌더 중 멱등 적용(`applyRootAttrs`).
- 캔버스 차트는 웹폰트가 늦게 오면 대체 서체로 그려진 채 남는다 → `document.fonts` `loadingdone`에서 토큰 재읽기.
- 등폭 서체(B612 Mono)는 '.' ':'가 한 칸이라 한글과 섞이면 "5. 5만"처럼 보인다 → 숫자는 비례폭 서체로.
- 다크 화면용 범주색을 밝게 고르면 검증기 다크 밴드(L 0.48~0.67)를 벗어나고 청록·파랑이 정상시에도 구분이 안 된다(ΔE 12.8) → 검증된 기존 팔레트로 회귀.
- 글래스는 처음엔 그래파이트와 구분이 안 될 만큼 밋밋했다 → 오로라 채도와 패널 하이라이트를 올리되 패널 불투명도는 유지.

- **기본 스타일 결정 (v0.5.1):** 사용자가 콕핏을 기본값으로 선택. `DEFAULT_STYLE = 'cockpit'`, 메뉴 맨 위에 '기본' 표시, `index.html`에도 `data-style="cockpit"`을 미리 넣어 첫 화면에서 다른 스타일이 깜빡이지 않게 했다. 이미 다른 스타일을 고른 사용자는 저장된 선택(localStorage)·링크(`#style-…`)가 우선한다.

## #6 렉 보드 v0.6 — 커맨드 센터 (2026-11-14)

요청: "배치와 스타일을 완전히 바꿔 줄 수 있어? 화려하고 동적인 스타일은 어때?" 근거·규칙 전문은 `knowledge/command-center.md`, 데모는 `docs/media/command-center.mp4`.

### 결정과 이유

| 주제 | 결정 | 이유 |
|---|---|---|
| 기존 화면 처리 | 새 화면(커맨드 센터)을 기본으로, 기존 보드는 "분석 보드"로 한 클릭 거리 | 벽 화면용 한눈 뷰와 원인 판별용 깊은 뷰는 목적이 다르다. 하나를 지우면 다른 쪽이 약해진다 |
| 주인공 | 세계 흐름 지도 1개 (지도 외 칸은 같은 크기) | Cloudflare Radar 2026 개편: 위젯 격자 → 지도 + 아래 세부. 벤토는 위계가 분명할 때만 |
| "화려함"의 재료 | 입자·소나·점 물듦·LED 등 전부 측정값이 구동 | GitHub 지구본: 움직임이 "살아 있다는 증거"여야 한다. 장식 모션은 경보를 묻는다 |
| 지도 기술 | d3-geo + world-atlas 110m → 오프스크린 래스터 → 육각 점묘, 2층 캔버스 | 의존성이 가볍고(3D 엔진 없음) 6개 DC 비교에는 평면이 정확하다. 60fps 확인 |
| 색 | 크롬은 낮은 불투명도 시안(콕핏 예외 계열), 강한 색은 등급·원인에만, 원인 팔레트는 분석 보드와 동일 | 네온 느낌을 색 수가 아니라 발광·테두리로 낸다. 두 화면에서 "인프라=파랑"이 유지된다 |
| 서체 | Chakra Petch(라틴·숫자) + Pretendard(한글) | 각진 테크 인상을 숫자에서 낸다. 한글은 가독성을 우선한다 |
| 화면 간 연결 | `Handoff` — 피드에서 장애를 고른 채 분석 보드로, HUD에서 권역을 넘김 | "보고 → 파고들기"가 한 동작이어야 한다 |

### 버그·교훈

- 공용 `button` 리셋이 배경·테두리를 지우지 않아 다크 회색 버튼 면이 카드에 깔렸다 → `:where(.cc) button` 리셋(특이도 0,0,1).
- 분석 보드의 전역 `.tier-warning { background }`가 새 화면의 같은 클래스에 칠해졌다 → 화면 접두어 클래스(`cc-t-*`, `cc-c-*`).
- 지역 카드를 고정 방향으로 붙이면 폭에 따라 잘리거나 겹친다 → 벌점 기반 자동 배치와 8개 크기 회귀 테스트.
- 납작한 지도(2.5:1)를 높은 칸에 넣으면 빈 띠가 생긴다 → 폭에 맞추고 위도를 더 보여 준다.
- 등장 시퀀스에서 점묘 층만 가리고 입자 층은 안 가렸다 → 두 캔버스에 같은 clip 애니메이션을 준다.
- 피드에서 재생하면 지도가 화면 밖이었다 → 재생 시 지도를 끌어올린다(`scroll-margin-top`).
- 24시간 창이 전날 21시부터라 "과거 21:06"이 모호했다 → 다른 날이면 날짜를 붙인다.
- 등장 애니메이션이 긴 화면은 QA 스크린샷이 반쯤 찍힌다 → `ui-shot.cjs`에 `WAIT_MS`를 추가했다.

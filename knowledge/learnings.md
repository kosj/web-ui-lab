## #1 렉 보드 v0.1 (2026-11-14)

### 결정과 이유

| 주제 | 결정 | 이유 |
|---|---|---|
| 정보 구조 | 요약 배너 → KPI → 권역×시간 히트맵 + 장애 판정 → 원인 분해 → 서버 그리드(권역→랙) → 서버 상세 → 방법 노트 | "어디서·언제부터·왜"를 위에서부터 답하고, 아래로 갈수록 근거가 구체화되는 깔때기 |
| 단일 지표 | 모든 렉 신호를 ms 하나(체감 지연 EL)로 환산 | 연구 임계값(100/150/250/500ms)을 그대로 쓰고, 성분이 가법이라 원인별 누적 영역으로 분해 가능 |
| 집계 | 권역·전역은 **동접 가중 p95**, 원인 분해만 가중 평균 | 꼬리 지연은 평균이 가린다. 분해는 가법성이 필요해서 평균을 쓰되 라벨로 명시 |
| 기준선 | **전일 동시간대 ±45분 중앙값** | 12h 롤링 중앙값은 저녁 피크를 이상으로 오탐(EU·NA 1시간짜리 가짜 장애 2건) → 계절성 기준선으로 해결 |
| 노이즈 | EWMA(α=0.35) 평활 z + 활성 5분 이상만 장애 | 단발 패킷 버스트로 생긴 6분짜리 가짜 장애 제거. "구간 길이"가 아니라 "활성 분 수"로 세야 한다 |
| 원인 판정 | 신호(z) + 토폴로지(같은 랙 2대↑ → 인프라) 2단계 | 지표만으로는 "서버 틱 증가"가 서버 탓인지 호스트 탓인지 모른다. 확산 범위가 결정적 단서 |
| 시작 시각 | CUSUM(k=0.5,h=5), **이후 10분 평균 z>2가 유지된 첫 경보** 채택 | 첫 경보를 무조건 쓰면 일시 경보 뒤의 리셋 때문에 시작이 24분 늦게 잡혔다 |
| 원인 색 | blue·aqua·violet·magenta (dataviz 기준 팔레트 슬롯 1·3·7·5) | 상태색(노랑·주황·빨강)과 겹치지 않게. 인접쌍 CVD ΔE 16+(다크) 검증. 리서치 노트의 Okabe-Ito 안은 인프라·네트워크 상호 대비 2.25:1이라 채택 안 함 |
| 상태 표현 | 색 + 아이콘 모양 + 한글 라벨, 필 안 글자는 노랑·주황엔 짙은 글자 | 색만으로 전달 금지. 주황(#ec835a) 위 흰 글자는 2.6:1이라 짙은 글자로 바꿈 |
| 크롬 | UI 컨트롤·선택·포커스는 무채색 | 색(hue)은 데이터·상태 전용. 선택 링은 잉크색 |
| 테마 | 다크 우선, 라이트 동등 지원. 호스트가 data-theme을 주면 따름 | 관제실 기본 + 사무실 공유 |
| 시간축 | 카테고리 축 + 직접 만든 KST 라벨, **구간 끝 시각**으로 라벨 | ECharts time 축은 브라우저 시간대를 따름. 시작 시각 라벨은 21:01처럼 정각이 어긋남 |
| 표 대안 | 히트맵·원인 분해에 "표로 보기" 토글 | 툴팁만으로 값을 읽게 하지 않는다 |
| 피드 상태 | 상단에 "수집 정상 · 36/36 서버" | 측정이 멈췄는데 정상으로 보이는 사고 방지 (Riot MSI 2022 사례) |

### 시각 QA에서 잡은 버그

- 렉 체감 유저 100% → 시나리오 강도 과다. 데모 데이터도 "대비"가 있어야 판단이 보인다(47%로 조정).
- 장애 레인 라벨 겹침 → 레인 높이 13→17px, `interval: 0`.
- 서버 그리드 6권역이 5+1로 줄바꿈 → 6열/3열/2열/1열 브레이크포인트로 고정 (혼자 남는 행 금지).
- 축 최대값 136.54 같은 소수 → `niceCeil`(1·2·2.5·5×10ⁿ).
- 임계선 라벨이 오른쪽 끝 데이터와 겹침 → `insideStartTop`(왼쪽)으로. 최신 데이터는 오른쪽에 몰린다.
- 모바일 히트맵 라벨 뭉개짐 → `hideOverlap: true` + 24h는 2시간 간격.
- 좁은 타일에서 "경고"가 "경/고"로 줄바꿈 → `white-space: nowrap` + foot `flex-wrap`.
- SVG 스파크라인을 `preserveAspectRatio=none`으로 늘리면 끝점 원이 타원이 됨 → 끝점은 HTML로 겹쳐 그림.

- ISP/ASN·클라 버전·기기 세그먼트 드릴다운, 선택 구간 vs 기준선 자동 비교(BubbleUp식).

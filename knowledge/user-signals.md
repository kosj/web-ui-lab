# 유저 체감 신호 — 채팅 렉 제보 × TCP 재전송 × 체감 지연

> 2026-11-14. 질문: "채팅 제보가 올라갈 때 TCP 재전송도 급증한다. 이 상관관계를 어떻게 보여 줄까?"
> 구현: `boards/lag-board/src/analytics/signals.ts`, `src/data/chat.ts`, UI `SignalChain`·`CouplingCard`·`IncidentMap`·`DoseResponse`·`ChatStream`.

## 1. 인과 사슬 — 왜 재전송인가

```
경로 패킷 손실 ──▶ TCP 재전송 ──▶ HOL 블로킹(뒤 패킷이 줄줄이 대기) ──▶ 멈칫·순간이동 ──▶ "튕김·끊김" 채팅
                  (RTO면 최소 200ms+, 지수 백오프)
```

- 대부분의 MMORPG는 TCP를 쓴다. 손실 하나가 그 뒤 데이터 전체를 막는다(head-of-line blocking).
  - RTO 기반 재전송은 정지 시간이 특히 길다. Linux의 최소 RTO는 200ms이고, RFC 6298의 권고값은 1s다.
- **판별력:** 클라 프레임 끊김이나 서버 틱 지연은 커널이 ACK를 정상적으로 보내므로 재전송이 늘지 않는다.
  - 그래서 "제보 + 재전송 동반"은 네트워크 손실형, "제보만"은 서버·인프라·클라·측정 사각지대다.
- 같은 체감 지연이라도 재전송이 많으면 유저가 더 불평한다.
  - 평균 지연에 담기지 않는 순간 정지가 따로 체감되기 때문이다.
  - MMORPG 연구(Chen et al. 2006)에서도 손실이 지연보다 3~4배 더 이탈을 부른다.

## 2. 통계 설계와 그 이유

| 단계 | 방법 | 이유 |
|---|---|---|
| 정규화 | 제보율 = 제보 유저 ÷ 채팅 유저(1만 명당·분) | 동접·채팅량 차이와 장애 때 채팅이 느는 효과 보정 |
| 기준선 | 전일 동시간대 ±45분 **합의 비**(Σ제보/Σ채팅유저) + 경험적 베이즈 수축 | 분당 비율의 중앙값은 건수가 적으면 0이 된다(v0.4 버그). 소규모 서버는 전체 비율 쪽으로 당긴다 |
| 편차 | 재전송·EL: 강건 z(중앙값·MAD) / 제보: 포아송 **Anscombe 잔차** 2(√(x+3/8)−√(λ+3/8)) | 원값끼리는 공통 일주기 때문에 허위 상관. 건수 데이터는 Anscombe가 소표본에서도 정규에 가깝다 |
| 동시 발생 | **사건 동시발생 분석(ECA)**: 서버 단위 급증 사건(z≥4, 3분↑, 15분 군집 해제), 촉발률·전조율, 우연 기대치 대비 포아송 꼬리확률 | "올라갈 때 같이 올라간다"는 연속 상관이 아니라 드문 급증의 동시 발생 문제 |
| 시차 | **사건 정렬 평균**(superposed epoch): 재전송 급증 시작을 0분에 맞춰 평균 ±95%, 사건 전 수준을 넘는 첫 분 = 상승 시점 | 분 단위 교차상관은 검정력이 없었다(아래 4절) |
| 효과 크기 | **분절 포아송 회귀**: log μ = log 채팅유저 + a + b·max(0, ln(EL/T)) + c·재전송 초과 + d·프레임 초과, T 격자 탐색, 프로파일 우도 95% 구간(준포아송 φ로 보정) | T = 유저가 불평하기 시작하는 체감 지연(임계값 재보정 근거), e^c = EL을 통제한 재전송 효과 |
| 사각지대 | 제보 z5 ≥ 4가 5분 이상 + 직전 15분 동안 EL 초과 < 20ms·재전송 z < 2 + 장애 앞뒤 15분 제외 | 제보는 체감 후 최대 12분까지 이어진다. 그 꼬리를 사각지대로 오탐하지 않도록 |
| 도배 | 유저 단위 중복 제거 + 같은 문구가 그 분 메시지의 절반 초과면 도배 유저 제외 | 스트리머 방문 "LAG KEKW" 같은 밈이 장애처럼 보이지 않게 |

## 3. 가상 데이터 정답과 회수 결과 (테스트로 고정)

| 정답(설계) | 분석 결과 |
|---|---|
| 꺾임점 T* = 175ms | 155ms (95% 150–155, φ 3.8) — 통신사별 체감 차이를 서버 평균 EL로 보기 때문에 약간 낮게 잡힘. 테스트 허용 ±30ms |
| 재전송 효과 e^0.35 = ×1.42 /1%p | ×1.41 |
| 제보 지연 1~12분(평균 약 2.9분) | 상승 시점 +4분, 급증 판정까지 중앙값 7분 |
| 동남아 케이블 손실 | 제보 급증 6건 모두 직전 재전송 급증(전조율 100%), 제보 ×40, 재전송 ×22 |
| LG U+ 단일 통신사 | 경로 재전송 ×5.4, 제보 ×1.9 (영향 유저 21%뿐이라 서버 단위 급증 판정은 안 됨) |
| 서버·인프라·클라 | 재전송 ×1.0~1.1(배제 근거), 제보 ×2~7 |
| 대만 로딩 사각지대 | 유일한 사각지대로 검출, 주요 표현 '로딩 지연' 80% |
| 북미 도배 | 도배 유저 360명 제외, 급증 판정 없음 |

전체 범위 ECA: 재전송 급증 14건 중 6건이 10분 안에 제보 급증으로 이어졌다(우연 기대 0.1건, p < 0.0001). 제보 급증 14건 중 8건은 재전송 없이 일어났다. 즉 **재전송 급증은 제보를 강하게 부르지만, 제보가 전부 재전송 때문은 아니다.** 이 비대칭이 원인 판별의 핵심이다.

## 4. 시도했다가 버린 것

- **분 단위 교차상관 + AR(1) 사전 백색화:**
  - 장애 구간이 길어 AR 계수가 0.99가 되면서 사실상 차분이 됐고, 급증 사건이 하루 몇 번뿐이라 상관 0.06(유의 띠 0.05)에 최대 시차도 엉뚱했다(−16분).
  - 결론: 연속적 공변동이 아니라 드문 급증의 결합은 사건 기반 방법(ECA, 사건 정렬 평균)으로 본다.
- **권역별 분절 회귀:**
  - 권역 하나에는 장애가 1~2건뿐이라 EL과 재전송이 함께 움직여(공선성) 재전송 효과가 ×0.73처럼 뒤집혔다.
  - 결론: 곡선은 항상 전체 서버로 적합하고, 권역 점만 겹친다.
- **사건 정렬 평균을 σ 그대로 한 축에:**
  - 재전송 z(최대 20)와 제보 z(1~2)의 크기 차이로 제보가 납작해졌다.
  - 결론: 이 차트는 타이밍용이므로 신호별 최대 반응을 100%로 맞추고, 효과 크기는 문장으로 쓴다.

## 5. 화면 구성 원칙

- **이중 축 금지:** 단위가 다른 세 신호는 같은 시간축의 세 칸에 쌓는다(신호 연쇄). ▼는 급증 사건 시작이다.
- **장애 지도:** 장애마다 재전송 배수 × 제보 배수를 로그 산점도로 그린다. 사분면 이름표를 달고, 점 크기는 영향 유저다. 표로도 보여 준다.
- **장애 판정 카드:** '제보' 근거와 'TCP 재전송' 근거(신호 또는 배제)를 자동으로 붙인다. 측정 사각지대는 별도 카드("제보 기반")로 띄운다.
- **채팅 표본:** 유형 막대를 한 색으로 그린다(범주형이므로 아이콘과 이름으로 구분). 렉 표현은 강조하고 닉네임은 가리며, 도배는 취소선으로 표시한다.
- **실데이터 전환 체크리스트:**
  - 언어별 키워드와 분류 정밀도를 검수한다.
  - 채널과 서버를 매핑한다.
  - 재전송 카운터 출처를 확인한다(서버 커널 TcpRetransSegs/OutSegs, eBPF tcp_retransmit_skb).
  - 통신사 단위 제보는 클라 텔레메트리와 연결될 때만 가능하다.
